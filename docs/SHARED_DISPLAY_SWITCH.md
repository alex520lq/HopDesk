# 共用显示器切换

适用接线：Windows 有一块保留的主屏，另一块扩展屏同时接到 Windows 和 Mac，靠输入源切换归属。普通双机各用独立屏幕时不要开启共屏模式。

## 设置

1. 首次设置时，在 Windows 中启用共用屏的“扩展”模式。HopDesk 需要取得原来的位置、分辨率和刷新率。
2. Windows HopDesk → 设置 → 显示器切换，开启“Windows 与 Mac 共用一块显示器”。根据界面列出的设备名、主屏标记和坐标，填写共用扩展屏的设备名，例如 `\\.\DISPLAY2`。设备名是 Windows 的名称，不等同于显示设置中的数字标签。主屏不能作为释放目标。
3. 确认 Windows/Mac 输入源值。旧脚本中的 BenQ PD2700U 接线是 Windows DP=`0x0F`、Mac HDMI=`0x11`，其他型号/接线必须实测确认，不能只按示例填写。
4. Mac 设置中的切源命令必须指向同一块物理显示器，例如 `m1ddc display 1 set input`。后台执行命令时会补入 `/opt/homebrew/bin` 和 `/usr/local/bin` 到 PATH。HopDesk 不安装 m1ddc。
5. 保存后使用概览页原有两个切屏按钮。Mac 端也可发起，Windows 是共屏拓扑的唯一协调者。无需 SSH 或另外保存 Mac 地址，使用已认证的 HopDesk 控制连接。

CLI 配置等价示例（Windows PowerShell）：

```powershell
.\HopDesk.exe config set disp_shared=true 'disp_device=\\.\DISPLAY2' disp_win_input=0x0F disp_mac_input=0x11 --json
```

共屏设置默认关闭。两端无法凭连接成功、分辨率、显示器数量或相同型号确认是同一块物理屏幕，因此必须明确选择。它不会自动更改用户正在使用的显示配置。

## 切换行为与所有权

- **交给 Mac**：收到 Mac 唤醒确认（至少一块外接屏已激活且未睡眠）→ 确保选定 Windows 扩展屏可访问 → 设置输入源并从 Windows 回读 VCP 0x60 → 保存原模式 → 从 Windows 桌面释放这一块扩展屏 → 重新枚举确认。Mac 唤醒确认不能证明选中的 m1ddc 屏幕与 Windows 目标是同一物理屏，接线/目标仍须人工核对。
- **交给 Windows**：恢复选定扩展屏及其原模式 → 重新枚举确认 → 切回 Windows 输入源并回读。Windows DDC 失败时可请求 Mac 执行配置的切源命令，仍以 Windows 回读为验收。
- 切源失败不释放扩展屏；释放失败尝试恢复 Windows 输出和输入源。回滚失败明确报错，需检查 Windows 显示设置及显示器 OSD。不会靠强制 Mac 睡眠掩盖失败。
- 只调整指定的非主屏，不执行影响整台机器的 `DisplaySwitch /external`、`/extend`。其他物理屏和虚拟屏不作为判定条件。
- Windows 原模式保存到配置文件旁的 `hopdesk.conf.display`，先原子写入并刷新磁盘，再修改显示拓扑；进程重启后可用同一配置恢复。不要在屏幕交给 Mac 时删除它。设备改名、换接显卡接口、替换显示器后，应先在 Windows 恢复扩展，再重新设置目标。
- 单个后台 Worker 串行切换；重复操作被拒绝。耗时 DDC、拓扑变更和 Mac 命令不在低级钩子或控制接收线程执行。请求 ID 与连接 epoch/session 隔离迟到回复。退出时先回收 Worker 再关闭网络对象。
- UI 的“已提交”仅表示请求接收；共屏模式只有拓扑和输入源验证通过才显示完成。普通模式保持原来的 DDC 输入源操作，不改变 Windows 拓扑；Mac 按钮通过 Windows 协调后执行 Mac 本机目标。
- 屏幕归属与键鼠提供方独立。切屏时先释放远端按键/按钮，切完仍需将鼠标推到配置边缘进入共享，不强制夺取键鼠提供权。

控制协议升级到 **v8**，数据协议仍为 v8。必须同时更新 Windows 和 Mac，并重启后台；旧控制协议会被拒绝，不支持混用。

## 测试与限制

共享生产流程测试覆盖双向顺序、唤醒失败、输入源失败、释放失败、回滚失败、Mac 切源兜底和帧字段校验。平台控制循环测试使用本机 TCP 和 API doubles，不代表显示器实测。

必须在真实 Windows + Mac + 共用显示器上验收：两端按钮发起、原位置/分辨率/刷新率恢复、切源后键鼠跨屏、DDC 关闭、Mac 睡眠/断线、重复点击、切换中重连/退出、进程重启恢复，以及附带虚拟屏的场景。未执行前均为待验证。主屏共享暂不支持；应保留一块 Windows 主屏作为本地控制入口。
